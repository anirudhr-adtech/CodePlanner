# MA plan: 17_apb_timer_watchdog

## S1. Partition TMRWDT into APB front-end, two timer instances, watchdog core, lock unit and IRQ/reset output logic

**Goal:** Write the Overview and Block Diagram. Fix the top-level partition: an APB3 slave and register decoder, two instances of one timer block (TIMER0, TIMER1), a WDT core (prescaler, counter, WARN/expiry logic, kick/window check), a WDT lock register, and the output logic for timer_irq, wdt_irq and wdt_rst_req. Confirm that everything runs on one clock, PCLK. List the design constants: KICK key, UNLOCK key, number of timers, and counter and prescaler widths.

**Feeds:** Overview, Block Diagram, Parameters · **Depends on:** none

**Spec evidence:**
- [P4] "two identical 32-bit general-purpose down-counting timers (TIMER0, TIMER1)"
- [P4] "one 32-bit watchdog (WDT)"
- [P2] "PCLK (up to 100 MHz)"
- [P4] "protected by a lock key."

**Decisions:**
- D1 Clock domain of the watchdog counter: **Single PCLK domain; the WDT counts on PCLK ticks generated by its PRESC prescaler** (decided)
  - options: Single PCLK domain for timers and WDT / Separate always-on WDT clock with CDC
  - The spec lists only PCLK and PRESETn, and WDT PRESC is defined as 'Count every PRESC+1 PCLK cycles'.

**Done when:**
- The block diagram shows the APB decoder, 2x timer instances, WDT core, lock unit and output logic, with all inter-block signals named
- Every top-level port (APB3 signals plus timer_irq, wdt_irq, wdt_rst_req) appears on the diagram
- Parameters/localparams are listed: KICK key 0x5A5A_A5A5, UNLOCK key 0x1ACC_E551, 32-bit counters, 8-bit PRESC, timer count = 2
- The Overview states that the design has a single clock domain

## S2. APB3 port list, zero-wait-state timing and unmapped-offset PSLVERR decode

**Goal:** Define the APB3 slave interface: PSEL, PENABLE, PWRITE, PADDR[11:0], PWDATA, PRDATA, PREADY=1, PSLVERR. Define the address decode for the two mapped regions (0x000-0x028 and 0x100-0x118). Define exactly which accesses raise PSLVERR, and what side effects occur, for unmapped, RO, WO and locked accesses.

**Feeds:** Interface, Timing & Pipeline · **Depends on:** S1

**Spec evidence:**
- [P2] "AMBA APB3, 32-bit data, 12-bit address offset, little-endian"
- [P19] "Zero wait states (PREADY tied high)."
- [P19] "PSLVERR is returned for accesses to unmapped offsets."
- [P7] "0x110 | WDT_KICK | WO"

**Decisions:**
- D2 PSLVERR scope for mapped-but-illegal accesses (write to RO register, read of WDT_KICK, write to a locked WDT register): **PSLVERR only for unmapped offsets. Writes to RO or locked registers are ignored without error. Reads of WDT_KICK return 0.** (default, medium impact, medium confidence)
  - options: PSLVERR only for unmapped offsets; illegal accesses to mapped registers are silently ignored or read 0 / Also return PSLVERR for writes to RO registers and to locked registers
  - The spec mentions PSLVERR only for unmapped offsets. Silent ignore is common for lock-protected watchdog registers.
- D3 Handling of PADDR[1:0] (non-word-aligned offsets): **Decode PADDR[11:2] only and ignore PADDR[1:0]** (default, low impact, medium confidence)
  - options: Decode PADDR[11:2] only, ignore PADDR[1:0] / Treat non-aligned offsets as unmapped (PSLVERR)
  - All registers are word-sized and APB3 has no byte strobes. Ignoring the low bits is the usual practice.

**Done when:**
- The port table lists each APB3 signal with width, direction and description, and states PREADY tied to 1
- The decode table maps every offset in P7 to a register select signal; all other offsets are flagged unmapped
- PSLVERR assertion is defined for the access phase (PSEL&PENABLE) and is shown to have no side effects on unmapped writes
- Read data for unmapped, WO and reserved locations is specified as 0

## S3. Register file field semantics: RW / RO / RW1C / WO / mixed WDT_STATUS and reset values

**Goal:** For every register in P7, specify storage (flop or derived value), the bits actually implemented, reset values (including WDT_LOAD and WDT_VALUE = 0xFFFF_FFFF and WDT_STATUS = 0x4), RW1C clear behaviour for IRQ_STATUS and WARN, and how reserved bits are dropped on write and zeroed on read. Specify the arbitration between a hardware set and a software clear of the same flag in the same cycle, and between a software write and a hardware update of the same register in the same cycle.

**Feeds:** Datapath, Control Logic, Clocking & Reset · **Depends on:** S2

**Spec evidence:**
- [P7] "IRQ_STATUS | RW1C"
- [P7] "0x114 | WDT_STATUS | mixed | 0x0000_0004"
- [P19] "Writes to reserved bits are ignored; reserved bits read as zero."
- [P8] "7:2 | – | reserved, read 0"
- [P14] "Window violation occurred (sticky until reset)"

**Decisions:**
- D4 Same-cycle priority between hardware flag set and software RW1C clear (IRQ_STATUS bits, WARN), and between a software write to Tn_CTRL.EN and the hardware one-shot EN clear: **A hardware set wins over an RW1C clear, so no event is lost. A software write to Tn_CTRL wins over the hardware one-shot EN clear.** (default, low impact, high confidence)
  - options: Hardware event wins / Software write wins
  - This is the industry-standard choice for status flags. It avoids losing interrupts while still letting software re-arm a timer deterministically.

**Done when:**
- A field-level table covers every register: implemented bits, access type, reset value, and storage/derivation
- IRQ_MASKED and WDT_STATUS.LOCKED are shown as derived (no own flop); WDT_VALUE and Tn_VALUE are read-only views of the counters
- WIN_VIOL is specified as read-only and set-only, cleared only by PRESETn
- The same-cycle priority rules from D4 are written as explicit next-state equations

## S4. Timer block datapath: 8-bit prescaler, 32-bit down counter, zero/reload/one-shot and compare-match logic

**Goal:** Specify one timer instance in full. Cover the prescaler that generates a tick every PRESC+1 cycles while EN=1, and the prescaler restart on a LOAD write. Cover the counter behaviour: decrement, at-zero handling, periodic reload, and one-shot stop with the hardware clearing EN. Cover generation of the ZERO and CMP events, and the event outputs sent to IRQ_STATUS.

**Feeds:** Datapath, Control Logic, Timing & Pipeline · **Depends on:** S3

**Spec evidence:**
- [P9] "Writing Tn_LOAD loads Tn_VALUE immediately and restarts the prescaler."
- [P9] "When the counter is at 0 and a count tick occurs: the ZERO flag is set."
- [P9] "In one-shot mode the counter stays at 0 and hardware"
- [P9] "When a count tick makes Tn_VALUE equal to Tn_CMP, the CMP flag is set."
- [P8] "15:8 | PRESC | Count every PRESC+1 PCLK cycles"

**Done when:**
- Next-state equations for prescaler count, Tn_VALUE and Tn_CTRL.EN cover the tick, load-write and idle cases
- The period is documented as (LOAD+1)*(PRESC+1) PCLK cycles in periodic mode
- The MA states whether a periodic reload to a value equal to CMP sets CMP (tick-caused, so yes) and that a LOAD write equal to CMP does not, recorded in Assumptions
- The prescaler behaviour when EN=0 and when PRESC changes mid-count is stated

## S5. Timer interrupt aggregation: IRQ_STATUS / IRQ_EN / IRQ_MASKED and timer_irq level output

**Goal:** Map the four timer events to IRQ_STATUS[3:0]. Define IRQ_MASKED as IRQ_STATUS & IRQ_EN. Generate timer_irq as the OR-reduction of IRQ_MASKED, and wdt_irq from WARN gated by INT_EN. Settle whether the outputs are registered or combinational from flops.

**Feeds:** Datapath, Interface, Timing & Pipeline · **Depends on:** S4

**Spec evidence:**
- [P10] "| 0 | T0_ZERO |"
- [P11] "timer_irq = |IRQ_MASKED[3:0]"
- [P5] "level, active high, watchdog warning interrupt."
- [P12] "3 | INT_EN | Enable warning interrupt"

**Decisions:**
- D5 Interrupt output generation: **timer_irq = |(IRQ_STATUS & IRQ_EN) and wdt_irq = WARN & INT_EN, both as combinational logic from flops** (default, low impact, medium confidence)
  - options: Combinational AND/OR of status and enable flops (no extra latency) / Registered outputs (one cycle extra latency)
  - The terms are pure AND/OR of flop outputs, so they are glitch-free enough for level interrupts and keep latency at zero. This matches the spec's formula.

**Done when:**
- The bit mapping of all four sources matches P10
- The output equations for timer_irq and wdt_irq are written out, with the event-to-output latency in cycles
- Clearing a status bit or its enable is shown to deassert the output in the next cycle

## S6. WDT lock unit: key-based unlock, scope of protection, LOCKED mirror

**Goal:** Define the lock flop: reset to locked, cleared by writing 0x1ACC_E551 to WDT_LOCK, set by any other write. Define the write-enable gating for WDT_LOAD, WDT_CTRL and WDT_WINDOW, and which registers stay writable while locked (WDT_KICK, WDT_STATUS.WARN clear, WDT_LOCK). Define the WDT_LOCK and WDT_STATUS.LOCKED read values.

**Feeds:** Control Logic, Clocking & Reset · **Depends on:** S3

**Spec evidence:**
- [P15] "Writing 0x1ACC_E551 unlocks WDT_LOAD, WDT_CTRL and WDT_WINDOW."
- [P15] "Reads return 1 when locked. Locked out of reset."
- [P14] "Mirrors lock state"

**Decisions:**
- D6 Registers covered by the lock: **Only WDT_LOAD, WDT_CTRL and WDT_WINDOW are write-protected. KICK, the WARN RW1C clear and WDT_LOCK are always writable.** (decided)
  - options: Only WDT_LOAD, WDT_CTRL, WDT_WINDOW (KICK, WARN clear always allowed) / Also block the WARN clear while locked
  - P15 lists exactly these three registers.

**Done when:**
- The lock flop reset value is 1 and its next-state equation is given
- Write enables for the three protected registers are gated by !locked
- WDT_LOCK and WDT_STATUS[2] reads both return the lock flop

## S7. WDT counter, prescaler and two-stage expiry (WARN then wdt_rst_req) control

**Goal:** Specify the WDT prescaler and the 32-bit down counter while EN=1. WDT_VALUE has exactly three update sources: kick_ok (valid, non-violating kick), wexpire (reload at expiry) and a tick decrement; a WDT_LOAD write and an EN 0->1 transition do not change it (per user answer Q1). Specify the first-expiry WARN set and reload, the second-expiry reset request gated by RES_EN, counter behaviour after a second expiry when RES_EN=0, and the sticky wdt_rst_req flop.

**Feeds:** Datapath, Control Logic, Timing & Pipeline · **Depends on:** S6

**Spec evidence:**
- [P17] "While EN = 1, WDT_VALUE counts down once per watchdog tick."
- [P17] "At the tick where WDT_VALUE is 0: if WARN = 0, set WARN and reload."
- [P5] "Once asserted it stays"
- [P12] "1 | RES_EN | Allow reset request"
- [P7] "0x104 | WDT_VALUE | RO | 0xFFFF_FFFF"

**Decisions:**
- D7 Effect of writing WDT_LOAD (or setting EN) on WDT_VALUE: **A WDT_LOAD write does not reload WDT_VALUE; the new LOAD takes effect only at the next valid kick or expiry. Setting EN does not reload; the counter resumes from its current WDT_VALUE. Only kick_ok, wexpire or a tick change WDT_VALUE.** (decided)
  - options: WDT_VALUE changes only on valid kick, expiry reload or tick / A WDT_LOAD write loads WDT_VALUE immediately, as the timers do / Setting EN 0->1 reloads WDT_VALUE from WDT_LOAD
  - Settled by user answer Q1.
- D8 Counter behaviour at the second expiry when RES_EN=0: **Reload from WDT_LOAD and keep counting, with WARN left set. Any later expiry while WARN=1 asserts wdt_rst_req if RES_EN has since been set.** (default, medium impact, medium confidence)
  - options: Reload and keep counting with WARN still set (each later expiry re-checks RES_EN) / Stop at 0 until kicked / Wrap to 0xFFFF_FFFF
  - Keeps the watchdog live and periodic, consistent with the first-expiry rule and with the Q1 answer that wexpire is a reload source.
- D9 WDT prescaler restart on valid kick: **Restart the WDT prescaler on kick_ok, as the timers do on a LOAD write; a window-violating kick does not restart it** (default, low impact, medium confidence)
  - options: Restart the prescaler on a valid kick (kick_ok) / Free-running prescaler unaffected by kicks
  - Gives a deterministic timeout after a kick and mirrors the timer rule in P9; consistent with violating kicks being otherwise ignored (Q2).

**Done when:**
- Next-state equations are given for WDT prescaler, WDT_VALUE, WARN and the wdt_rst_req flop, with priority among kick_ok, tick, expiry and RW1C
- The WDT_VALUE equation contains only kick_ok, wexpire and tick terms; no WDT_LOAD-write or EN-edge term exists
- The worst-case timeout from a kick to wdt_rst_req is derived as about 2*(LOAD+1)*(PRESC+1) cycles
- wdt_rst_req is shown to have no clear path other than PRESETn
- The reset values 0xFFFF_FFFF for WDT_LOAD and WDT_VALUE are reflected

## S8. Kick key detection and window-violation logic

**Goal:** Define kick detection (a write of 0x5A5A_A5A5 to WDT_KICK), win_bad = WIN_EN & (WDT_VALUE > WDT_WINDOW) sampled in the kick write cycle, and kick_ok = kick & ~win_bad. A violating kick sets the sticky WIN_VIOL and asserts wdt_rst_req if RES_EN=1, and is otherwise ignored (no reload, no WARN clear) per user answer Q2. Define treatment of non-key writes.

**Feeds:** Control Logic, Datapath, Corner Cases & Error Handling · **Depends on:** S7

**Spec evidence:**
- [P13] "Writing 0x5A5A_A5A5 reloads WDT_VALUE from WDT_LOAD and clears WARN."
- [P13] "If WIN_EN = 1 and WDT_VALUE > WDT_WINDOW at the time of the kick"
- [P17] "A window violation asserts `wdt_rst_req` immediately if RES_EN = 1."

**Decisions:**
- D10 Effect of a window-violating kick on reload and WARN: **A window-violating kick sets WIN_VIOL and asserts wdt_rst_req if RES_EN=1; otherwise it is ignored: kick_ok = kick & ~win_bad, so no reload and no WARN clear.** (decided)
  - options: Flag the violation and still reload and clear WARN / Flag the violation and ignore the kick (no reload, WARN unchanged)
  - Settled by user answer Q2.
- D11 Writes to WDT_KICK with a value other than the key: **Ignored with no effect and no PSLVERR** (default, low impact, medium confidence)
  - options: Ignored, no effect / Treated as a violation that sets the reset request
  - The spec defines only the key value and does not say that a wrong key is an error.

**Done when:**
- kick, win_bad and kick_ok equations are specified, including that the window check uses the pre-kick WDT_VALUE
- It is explicit that a violating kick neither reloads WDT_VALUE nor clears WARN, and that with RES_EN=0 it only sets WIN_VIOL
- Behaviour is stated for a kick while EN=0, a kick while WIN_EN=0, and a kick coinciding with a tick or expiry
- WIN_VIOL is set-only, and both WIN_VIOL and the immediate rst_req path are drawn in the control diagram

## S9. Reset and clocking: PRESETn-only reset of all state, including the sticky reset request

**Goal:** Document the single clock domain and the active-low reset style. List the reset value of every flop, matching P7, and the post-reset state: WDT disabled, locked, VALUE=0xFFFF_FFFF.

**Feeds:** Clocking & Reset · **Depends on:** S5, S8

**Spec evidence:**
- [P2] "PRESETn, active low"
- [P15] "Reads return 1 when locked. Locked out of reset."
- [P5] "Once asserted it stays"

**Decisions:**
- D12 Reset style for PRESETn: **Asynchronous active-low reset on all flops, following APB convention** (default, low impact, high confidence)
  - options: Asynchronous assert, flops reset on PRESETn low / Fully synchronous reset
  - APB peripherals conventionally use async PRESETn. The upstream system is assumed to synchronise deassertion.

**Done when:**
- A table lists every state element with its reset value, consistent with P7
- The text states that wdt_rst_req and WIN_VIOL clear only on PRESETn
- The reset style and the deassertion assumption are documented
